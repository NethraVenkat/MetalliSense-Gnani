### Failed takes

- **Gate take 1.** Single utterance. The 1.5 s wake snippet ended inside a pause, so the app waited for a new command after the clip had finished. No command ran.
- **Gate take 2.** A wake-only clip cut from the gate clip was heard as `ம்ம்.` Wake not detected. The wake clip was then rebuilt from the Tamil clip, which Prisma hears as `குரல்`.
- **Gate take 3.** Hold-to-talk path. Prisma returned `குரல் gate check பண்ணு, ஏஜாயிரத்தி ஐம்பத்தொன்று.` The leading wake word is not stripped on that path, so the app answered that it had no such information.
- **Approval take 1.** The approval executed, but the first code was refused as "six digits not heard", not as a wrong code. Not used. A new wrong-code clip was generated.
- **Approval take 2.** Harness setup error: the backend refused a second pig iron request, so no pending PR existed. The beat never started and made no Gnani call. A DRI request was created for take 3.

## Honesty notes

- **No mocks in the video.** Zero-call dry runs with mocked provider routes were used only to test the harness. They are in folders ending `-dry` and nothing from them is in any video.
- **No splicing across takes.** Every beat uses one take. No reply is attached to a command from another take.
- **No speed changes.** Waiting was removed with hard cuts only. Cuts fall on provider latency, the 5 s approval countdown, the gate read-back and cancel window, and the approval read-back.
- **Replies are cut short.** The Tamil status answer runs 23.2 s and is cut after 8.6 s. The refusal, the wrong-code reply and the Hindi question are also cut before they end. The captions quote the real reply text.
- **The gate check did not use the spoken heat number.** Prisma rendered "H-1051" as Tamil number words and the app did not resolve them to a heat ID. The check ran on the heat selected on screen, which was H-1051. The on-screen caption says "on the selected heat". Do not claim the spoken ID was parsed.
- **The Tamil status question did resolve 1053 from speech.**
- **Wake word delivery.** In beats 1 and 2 the wake word and command are one utterance. In the gate, approval and Hindi beats the operator says "Kural", waits for Listening, then speaks the command. The wake word in all three is the same Timbre-generated Tamil "குரல்" clip. The approval beat's wake is not shown because of the time limit; the caption for that beat does not include the word "Kural".
- **Two cached replies.** In approval take 3 the passcode prompt and the final "முடிஞ்சது." were served from the isolated cache. Both had been generated live by Timbre in approval take 1 a few minutes earlier in the same session. Every other reply in the video was a live call.
- **Audio tags.** `TTS_AUDIO_TAGS=true` for every Kural reply. All replies came from `gnani:timbre-v3.0:Kalpana`; no fallback voice was used.
- **Passcode.** The digits are never shown or played. The app shows ••••••, the captions show ●●●●●● and the two code segments carry no audio. The code file and all audio containing the digits were deleted after rendering. The identity existed only in the stopped isolated Agent.
- **Synthetic plant data.** Heats, lots and purchase requests are the backend's demo seed plus two purchase requests created for the takes. The H-1053 gate result was produced by the real gate before the take.
- **Voiceover lines not verified against the cut.** Several suggested lines do not fit the clean gaps. `voiceover_cues.md` says where ducking is needed.
